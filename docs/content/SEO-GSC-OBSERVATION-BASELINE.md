### 判读纪律（**提前钉死，避免将来自己找理由重开**）

- **收录慢 ≠ 有问题**。新站/新页面进入索引通常需要数天到数周。
- **Impressions 0 但已抓取** = 正常爬取期，继续等。
- **Indexed < 14** 不自动等于失败：Google 本就允许「发现但不收录」（内容质量、
  站点权重、竞争度都会影响）。
- **首页可见正文仅 21 字符**（O-SEO-08）⇒ 首页被收录但无排名是**预期结果**，
  **不构成「首页没优化好」的证据**，也不构成重开理由。看首页时只关心
  `URL is on Google` 与 canonical 是否正确，**不拿它的 impressions 判断内容质量**。
- **只有当 Google-selected canonical 与我们声明的不一致，或页面被判 `noindex` / `Crawled - no**
  时，才是**需要动手**的信号。
- 判定的**唯一依据是 Google 端数据**，不是「还能优化什么」。

## 五之二、下一观察周期的判定门槛（**2026-10-06 冻结 · 看数据之前定死**）

⚠️ **本节的价值全在「前置」。** 若等数据回来再定门槛，门槛会被定成刚好能解释现状的样子。
**以下判定在拿到第一批 GSC 数据前就已写定，此后不得因数据难看而放宽。**

### 依据（Google 官方口径，非本项目估计）

| 事实 | 官方表述 |
|---|---|
| 提交后立即抓取 | Google 在收到 sitemap 后**立即尝试抓取**；若失败会在**数天内**持续重试，成功后按自身节奏反复重抓 |
| `Discovered - currently not indexed` | Google 已发现该 URL 但**尚未抓取**。官方解释：抓取会给站点带来过载，故**重新安排了抓取时间** ⇒ 这是**抓取调度问题，不是内容判决** |
| `Crawled - currently not indexed` | Google **已抓取**该页但**决定不收录**。官方明确：**无需重新提交该 URL** |
| 单页问题不阻塞 sitemap | 只要 sitemap 大体可抓取可读，**个别 URL 的问题不会阻止 Google 继续读取 sitemap** |
| 低质量页面的典型形态 | 官方列举：过时内容、站内搜索框生成页、**应用过滤器生成页**、重复内容、自动生成内容 |

> 🕐 **时间门槛（业界经验值，非 Google 承诺）**：sitemap 状态变Success 数小时～1 天；
> URL discovered 约 1–7 天；新站首次收录通常 2–6 周。
> **本项目只有 14 个 URL、站点权重近零** ⇒ 取区间下沿之外不判失败，但**也不因此放宽 canonical 红线**。

### 门槛 A：canonical 一致性（**红线 · 唯一可立即判定失败项**）

| 观测 | 判定 | 动作 |
|---|---|---|
| `User-declared canonical` == Day 0 本地声明值（§四之二） | ✅ 一致 | 记录，**继续等** |
| `User-declared canonical` ≠ 本地声明值 | 🔴 **失败** | 立即立刀（我方或 Google 侧有偏差，属可判定缺陷） |
| `Google-selected canonical` == `User-declared canonical` | ✅ 规范化闭环成立 | 记录 |
| `Google-selected canonical` 指向别的地址 | 🟡 **观察项 O-SEO-09** | ⛔ **不重开 Path C**。先看是否同批 308 规范化未完成；仅当**持续多次巡检仍偏离**才升级 |
| 出现 `Alternate page with proper canonical tag` | ✅ **预期正确行为** | 记录，**不是**问题 |

> 🔴 **canonical 是唯一「不需要等数据成熟就能判失败」的红线。** 其余一切都可以等。

### 门槛 B：收录状态是否与页面形态相符（**不是「收录 = 好」**）

**先认状态类型再判好坏** —— `Discovered` 与 `Crawled` 是方向相反的两件事：

| GSC 状态 | 含义 | 是否失败 | 正确动作 |
|---|---|---|---|
| 已收录 | 在索引里 | — | 记录 |
| `Discovered - currently not indexed` | **还没抓** | ❌ **不是失败**（官方：抓取调度） | **等**。⛔ 改内容 / 改结构一律无效 |
| `Crawled - currently not indexed` | 抓了，**判不收录** | 🟡 **内容层信号，不是技术缺陷** | ⛔ **不重开 Path C**；仅记录哪个包被拒（推测与厚度相关，见下表） |
| `Excluded by robots.txt` | 被拦 | 🔴 **失败** | 但本地已实测零 Disallow ⇒ 若出现必为 Google 侧异常，立刀 |
| 404 / 5xx | 抓取失败 | 🔴 **失败** | 但本地 14/14 = 200 ⇒ 若出现立刀 |
| `Duplicate without user-selected canonical` | 判重复 | 🟡 观察项 | 记录，⛔ 不重开 |

**按 Day 0 本地厚度基线的预期形态**（这是**事前**预测，不是事后解释）：

| 页面 | 可见正文 | 事前预期 | 若结果不同，说明什么 |
|---|---|---|---|
| `kaoyan` / `ielts` / `toefl` | ~28000–29000 | **最可能先被收录** | 若这批最厚的页反而 `Crawled - not indexed` ⇒ 问题**不在厚度**，需重查内链 / 规范化 |
| `cet4` / `cet6` | 7659 / 5918 | 次之 | — |
| 小包（`ai-core` / `cloud-native` / 三个 `ielts-*-vocab`） | 751–2973 | **可能长期不收录** | ⚠️ 这是**预期结果**，⛔ **不得据此临时灌水扩充**（O-SEO-03 / O-SEO-06） |
| **`frontend`** | **547** | **最可能被判低价值** | ⚠️ 若 `Crawled - not indexed` ⇒ **完全符合预期**，**不是 Phase 1 失败** |
| `/`（首页） | **21** | 收录与否均不意外 | ⛔ **不拿首页判断内容质量**（O-SEO-08） |

> 🔑 **厚度预期表是本节的核心用途。** 有了它，`frontend` 被拒在**事前**就是可预期的，
> 于是它在**事后**不构成新信息，也就**不构成重开理由**。

### 门槛 C：Impressions / Clicks（**只在有足够曝光量后才判**）

| 情形 | 判定 |
|---|---|
| Impressions = 0 且 Indexed = 0 | ❌ **不是失败**（还没进索引，谈不上曝光） |
| Impressions = 0 但 Indexed > 0 | 🟡 正常爬取期，**等** |
| 有 Impressions 但 Clicks = 0 | 🟡 观察（可能排名靠后或 CTR 低），**等更多数据** |
| 有 Clicks | ✅ 闭环真正产生价值，**记录 queries 看用户搜什么** |

> ⛔ **判读必须与「页面厚度 + 收录数」联合看。** 单看平均排名对 14 个 URL 的新站无意义。
> ⛔ **queries 才是「下一刀」的依据**：哪个查询带来了曝光，就扩展**那类**内容——
> 而不是我方「还能优化什么」。

### 冻结声明

本节判定在**无任何 GSC 数据**的状态下写定（Day 0 = 2026-10-06）。
后续任何调整**必须记录调整理由与触发它的具体数据**，⛔ 不得因数据不理想而静默放宽。
唯一例外：**Google 官方口径被本项目实测证伪时**（官方说 X、实测非 X），按实测为准并留痕。

| **O-SEO-05**（新· 台账自身缺陷，已修） | 本台账早期版本的 4 个正文长度**混用了「含 script」与「不含 script」两套口径**（`ielts` 用不含script，另 3 页用含 script），导致 `frontend` 被记为 1528（真值 **547**）、`toefl` 记为 28867（真值 **27886**）、`kaoyan` 记为 30087（真值 **29106**）；另有`ielts` 字节数 73967 的**数字转置错误**（真值 **73957**）。**根因已实测定位：差值恒定 981 = 13 页共享的同一内联 `<style>` 块**。⇒ **已全部更正，并在 §二C 明写口径**。教训：**混用口径的数字不能横向比较**，一旦混用即等于没有基线 |
| **O-SEO-06**（新） | 三个大包 `words.json` 各 **3000** 词，页面只渲染 **300** 词（10%）。这是 Phase 1 的**明确设计**（`WORDS_PER_PAGE = 300`，不做分页），页面也如实声明「展示前 300 / 完整 3000」。⚠️ 但 Google 看到的是「自称 3000 却只列 300」的页面，对内容完整性判断是**负面信号**。⛔ **不在本刀扩为分页**；仅当 GSC 真实数据显示这些包有曝光潜力时，才作为**下一刀的依据**（而不是现在凭工程感觉做） |
| **O-SEO-07**（新） | `robots.txt` 用**相对路径** `Sitemap: /sitemap.xml`。Google 按 robots.txt 所在 host 解析，**实际可用**（实测正常放行），但官方规范用绝对 URL。一旦将来加CDN 子域或换主机，解析基准会变。属**可接受但非最佳实践**，登记观察 |
| **O-SEO-08**（新） | **首页可见正文仅 21 字符**且**无 `meta description`**——`<body>` 仍是 SPA 空壳 `<div id="root">`。与 Phase 0 取证一致，**本刀未处理、不在 Path C 范围**（首页是 SPA，不属「静态索引页」）。⇒ **13 个词库页是当前唯一的可索引正文来源**，首页在 GSC 眼里近乎空壳。⛔ **不因此重开 Path C**、不改首页（那是 SPA 渲染，静态化属另一条独立议题，届时须单独立刀） |
| **O-SEO-09**（新 · 观察期新增） | `Google-selected canonical` 偏离 `User-declared canonical`。**处置见 §五之二 门槛 A**：⛔ 不重开 Path C，先看是否同批 308 规范化未完成；**仅当持续多次巡检仍偏离才升级为独立刀**。单次偏离不作为「canonical 修复没做干净」的证据 |

### 本轮落档时的一条工程纪律（第9 条的实例）

台账初稿里的正文长度数字**内部并不矛盾、门禁也不管它**——它错在「混用两套口径」这个只有
**横向比较**才能发现的问题。发现它的不是任何既有门禁，而是一次**独立复核**（同一份数据由
第二个执行者用不同取样重算）。

⇒ **凡是要被横向比较的度量，落地时必须写明口径**；否则「有数字」会给出「已建立基线」的错觉。
这是 `判据一致 ≠ 语义正确` 的第9 条纪律在**文档层**的形态。

### 本轮（§一 更新）的一条工程纪律（第 11 条）

> **「能力不存在」和「我没找过」是两件事。**

我前两轮判定「本机无 GSC 通道」，依据是「无 API 凭据 + 无连接器」——
这两项都成立，**但都不是通道的完备枚举**：我漏了**已登录的浏览器会话**。
真实通道一直在本机开着（Chrome + CDP 9222）。

⇒ **判定「做不到」之前，必须把通道枚举完整。** 至少覆盖：
`API 凭据 → 连接器/MCP → 本机 CLI → 已登录浏览器会话（CDP/扩展）→ 本地文件/缓存`。
本项目此前踩过同型坑（§6c：只看 `dist/` 就断言 canonical 正确，漏了托管层的 308）——
**共性都是「只检查了自己能检查的那一层」**。

⚠️ 注意本条与既有纪律的**边界差异**：这不是「门禁失效」，而是**调查不完整**。
两者都会导出错误的「不可能」结论，但修法不同：前者补判据，后者**补枚举**。
