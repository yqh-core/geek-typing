## 硬阻塞：manifest 容量口径失真（已解）

| | 改前 | 改后 |
|---|---|---|
| 全库 manifest（原始字节） | 39,139 B | 39,139 B（不变） |
| 全库 manifest（**常驻字段口径**） | 该口径当时不存在 | **18,502 B** |
| 阈值 | 40,960 B | **65,536 B** |
| 余量 | 1,821 B | **47,034 B** |
| 均值 | 1,450 B/包 | **685 B/包** |

⇒ **按新口径可再加约 68 个包（≈22 套三包单元）**，而旧口径只够 1.25 套。

**为什么原口径失真**：`scripts/content/manifest-runtime.mjs` 的
`DROPPED_MANIFEST_FIELDS = ['sources','contentHistory','build']` 三字段在构建期已被裁掉、
**根本不进主 chunk**（实测三者合计 764 B/包，占单包 53%），而判据 18 卡的却是**磁盘原始总字节**。
且阈值注释写着「实测 10 包 13.08 KiB；阈值按 **40 包**规模预留」—— 而实际已27 包、均值 1,450 B/包，
**阈值的世界观与增长现实脱节**。

**yqh 裁定的三条口径纪律**（已写进代码注释）：
```
Manifest budget = runtime-resident fields only
Excluded         = build-time-only fields (already stripped from main chunk)
Hard limit       = 64 KiB
```
目的：**防止再次出现「注释说 40 包、实际只剩 27 包」的口径漂移。**

### ⚠️ `.gitattributes` 的 `-text` 是必须的

`unit-source-ielts-tech-03.json` 实测带 **CRLF（578 个 CR）**，而全仓是 `* text=auto eol=lf`：

| | blob 字节 |
|---|---|
| 无 `content-source/** -text` | 28,725 B（**CR 被静默吞掉，入库即失真 578 B**） |
| 有 `-text` | 29,303 B（与工作区逐字节相同） |

**为什么不是洁癖**：`--check` 与判据都要对源做 SHA-256 与 JSON 语义比对，

## 顺手修的一行 bug

`scripts/content/ingest.mjs:208` 排除的是 `_generatedAt`，但产物键名是 **`generatedAt`**（无下划线）
⇒ 从未被排除 ⇒ **每次比较都不等⇒ 每次跑都重写文件**。
而该文件 `:207` 的注释却自称「`_generatedAt`：它每跑必变、刻意不参与语义比较」—— **注释与实现不符**。

修后验收：`run1` 落盘 → `run2`/`run3` 均打印「产物语义未变，跳过写入」，`git status` 为空。

⛔ **未用「lint 通过」换回错误键名**：解构写法 `({generatedAt, ...rest})` 会被 oxlint 判红（未用参数须带 `_`），
而写成 `_generatedAt` 虽过 lint、**恰恰是这次要修的错键名** ⇒ 改用复制 + delete，键名写在字符串里。
