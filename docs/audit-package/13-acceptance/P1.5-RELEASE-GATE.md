## G1 · 身份一致性门禁

**这道门禁在问什么**：全站是否还有「用 `toLowerCase()` 绕开 ContentId 大小写敏感」的地方？Learning 键、ContentId key、检索 key 三者的口径是否已经**只剩一处实现**？

**背景（`[实测]` 事实）**：`[实测]` 真实语料 `contentCaseCollisions = 0`（即不存在「同一 lowercase 对应多个原词形」），`lowerToPkgs distinct = 6713` 与 `wordToPkgs distinct = 6713` 完全相等 —— **这正是 0 冲突的直接原因**。但 `go-code` / `ts-code` 两包声明 case-sensitive（词条如 `useEffect` / `treeShaking`），一旦语料引入大写变体，任何 lowercase 旁路都会立刻变成**静默错数据**。

### D.5 ⚠️ 一次 flaky 的完整归因（**不是本轮改动导致**，已定位到具体断言）

**失败断言**（`tests/offline-audit.mjs:238`）：
```
态2: 断网下敲正确字母光标前进 — r → r          ← FAIL
```

**断言代码**：
```js
const c0 = await readCursor(page)
for (const ch of w1.slice(0, 3)) await page.keyboard.press(ch)
await page.waitForTimeout(250)                  // ← 固定等待
const c1 = await readCursor(page)
check('...', c0 !== null && c1 !== null && c0 !== c1, `${c0 ?? 'null'} → ${c1 ?? 'null'}`)
```
`readCursor`（`:64-67`）= 读 `[data-state="cursor"]` 的 **`data-letter` 属性值**（不是下标）。

**根因（两个叠加因素）**：

1. **被测词是 9 字母长词 `retrieval`**（本次实测 `单词=retrieval`）。脚本按下 `w1.slice(0,3)` = `'r','e','t'`，
   光标前进 3 格后落在第 4 个字符上 —— `retrieval` 的字符序列是 `r e t r i e v a l`，
   **第 4 个字符恰好又是 `r`，与第 1 个相同**。于是 `c0='r'`、`c1='r'`：

   ```
   单词: retrieval  长度 9
   字符序列: r e t r i e v a l
   slice(0,3) = ret
   光标应落在第 4 个字符 = r
   第1个字符 = r
   两者相同? true      ← 这就是 r → r 的原因
   ```

   **这不是「光标没动」，而是「光标动了 3 格，但首尾字母同形」。** 断言用
   「`data-letter` 值不相等」代替「光标下标递增」，属于**判据选择错误**：
   凡「第 4 个字符 == 第 1 个字符」的词都会误判（`retrieval` 命中；`banana`/`level`/`avocado` 都不命中 —— 已实测）。
   由于每轮词表随机（`gt.shuffle` 默认 `true`），该断言**约有一定概率红**，与词表分布相关。
2. **叠加时序竞态**：`waitForTimeout(250)` 是固定等待。CI / 冷启动慢时会读到渲染中途快照 ——
   但**本例的 `r → r` 不是这个原因**（两个值都非 null，说明 DOM 已就绪，读到的是「已前进 3 格」的正确状态）。
   时序竞态是**同一断言的第二个独立风险**，需分开处置。

**为什么不是本轮改动导致**：本轮只新增脚本（`migration-dryrun.mjs` 等）与文档，**`src/` 零改动**
（`git status src/` 的两行是本轮之前的既有未提交改动）。且失败点在断网打字路径，
与 Learning / 迁移 / Query 层无任何调用关系。

**判定**：**真实存在的测试缺陷**（判据选择错误 + 潜在时序竞态），
**不是**产品缺陷，**不是**本轮回归。连跑 3 次全绿，因为随机词表里「第 4 字符 == 第 1 字符」是少数形态，
不是每次都撞上。

**已实施修复（2026-09-27 晚，`tests/offline-audit.mjs`）**：三个缺陷一并修掉，判据**变强**而非放宽。

| 缺陷 | 修法 |
|---|---|
| ① 判据选择错误：用「字母值不同」代替「下标前进」 | `readCursor()` → **`readCursorIndex()`**：返回光标**下标**（首词元素内 `findIndex`），不再依赖字符值 |
| ② 词长 ≤ 3 时敲满整词 ⇒ 无 `cursor` 元素 ⇒ `c1 === null` 判红 | `typeCount = min(3, max(1, len-1))`：**永远留一个字符给光标**，不触发整词完成/轮次推进 |
| ③ `waitForTimeout(250)` 固定等待的时序竞态 | 改 `waitForCursorIndex(expected)` **轮询**（≤5s），读的是渲染完成态，不是半途快照 |

断言同时从「`c0 !== c1`」升级为**「`c0 === 0 && c1 === typeCount`」**（精确期望下标）。
这两个断言互为内置对照组：若某天读取函数退化成返回常数，初值期望 0 与终值期望 3 必有其一转红。
