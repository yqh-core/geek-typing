### 1.4 "发音"不是"音频"

| 概念 | 现状 | 涉及测试 |
|---|---|---|
| **发音（TTS）** | ✅ 已实现，用浏览器 `SpeechSynthesis` API | `tests/e2e.mjs:255`【8.5】发音与数据分析；`tests/e2e.mjs:538`【13】代码模式与发音增强 |

## 3. 待建测试方案（音频）

### 3.1 内容层门禁（应加入 `scripts/content/validate.mjs`）

当前第 12 项 (f) 只在 `manifest.assets` 存在时才校验。**这不足以覆盖 `words.json` 里的词条级音频引用。**

建议新增第 21 项：

```
21. 媒体资产一致性：
    (a) manifest.assets 里每个路径必须指向真实存在的文件
    (b) 每个资产的文件头必须与声明的 MIME 一致（不只看扩展名）
    (c) 单资产体积上限（需先定阈值）
    (d) 全库资产体积上限
    (e) 词条 audio 字段引用的资产必须存在（或明确允许外链）
    (f) 无孤儿资产（存在的文件必须在某处被引用）
```

**(b) 是关键**：只看扩展名会被 `.mp3` 改名的任意文件骗过。这是 `SECURITY_TEST.md` 里 MIME 欺骗问题在内容层的对应面。

### 3.2 运行时测试（应加入 `tests/e2e.mjs`）

| # | 断言 | 期望 |
|---|---|---|
| 1 | 切词库后音频元素数量与启用词条数匹配 | 一致 |
| 2 | 点击发音按钮 → 音频请求发出且返回 200 | 200 |
| 3 | 音频加载失败（mock 404）→ **UI 有可见反馈** | 有反馈（当前无，同 `UX-002`） |
| 4 | 音频播放中切换词条 → 旧音频停止 | 无重叠播放 |
| 5 | 断网后已缓存音频可播 | 可播 |
| 6 | 断网后未缓存音频 → 优雅降级 | 无 `ERR_FAILED` 中断交互 |
| 7 | 连续快速点击 10 次发音 → 不卡死、不叠 10 路播放 | 有限流 |
| 8 | 无 `SpeechSynthesis` 环境 → 按钮禁用或降级 | 不崩 |

**第 3 条与第 6 条是重点**：媒体加载失败在真实环境里非常常见（弱网、CORS、CDN 抖动）。当前代码里**没有任何失败路径的用户反馈**（`UX-002` 记录的是词库加载，媒体同理）。

## 4. 与 SW / 离线的关系（重要）

`public/sw.js`（178 行）的缓存策略实测：

| 路径 | 策略 |
|---|---|
| `/assets/*` | **cache-first** |
| 其余 | **network-first**，断网回落 `caches.match(req) \|\| caches.match('/index.html') \|\| caches.match('/')` |

**关键问题**：如果未来音频放在 `/audio/*` 或 `/media/*`，**它们不在 `/assets/*` 的 cache-first 规则内**，会走 network-first ⇒ 断网时**只能靠运行时缓存命中**，无法保证离线可播。

且 `precacheShell()` 的实现（`public/sw.js`）是：

```js
// 解析首页 HTML 正则 /(?:src|href)="(\/assets\/[^"]+)"/g 纳入 assets
```

**只解析首页 HTML 里出现的 `/assets/*` 引用**。音频如果是运行时动态请求的，**根本不会进预缓存**。

⇒ **引入音频必须同步改造 SW 策略**，否则会出现"在线能听、离线无声"的静默退化（对比 `UX-001`：当前连离线状态 UI 都没有）。

## 6. 一句话总结给审计方

**媒体（音频/视频）是两个完全空白的能力域。当前唯一的"声音"是浏览器 TTS 发音，它不加载任何文件、不占任何体积、不参与 SW 缓存。门禁第 12 项 (f) 里已写好 broken-asset 校验分支，但因为零资产数据，这段代码从未被执行过。**
