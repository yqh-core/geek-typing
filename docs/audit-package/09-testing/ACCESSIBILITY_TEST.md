## 2. 为什么这个缺口在产品语境下更严重

这不是一个内容网站，是一个**"打字练习 + 背单词"工具**。它的目标用户群与无障碍的关系很直接：

| 用户群 | 关联 |
|---|---|
| 视力障碍用户 | 打字练习对盲打训练有价值，但需要屏幕阅读器可读 |
| 运动障碍用户 | 键盘流操作是优势，但需要可配置、不需要精确鼠标 |
| 阅读障碍用户 | 对比度、字距、reduced-motion 直接影响可用性 |
| 低视力用户 | 缩放支持是硬需求 |
| 色觉障碍用户 | 打字正确/错误的状态若只靠颜色区分 ⇒ 不可用 |

**最后一条尤其关键**：打字练习必然有"打对了/打错了"的状态反馈。**如果这个反馈只靠颜色（绿/红），色觉障碍用户完全无法使用本产品。**

**当前无任何断言验证"状态反馈不只靠颜色"。** 这是一个功能可用性问题，不只是合规问题。

## 3. 待建测试方案

### 3.1 自动化 a11y 扫描（成本最低）

建议用 axe-core（可通过 `playwright-core` 注入 CDN 或本地打包的 axe）：

| # | 断言 | 页面 |
|---|---|---|
| A-1 | 首页零 axe 严重违规 | Home |
| A-2 | 打字页零 axe 严重违规 | Typing |
| A-3 | 背单词页零 axe 严重违规 | Memorize |
| A-4 | 结算弹层零 axe 严重违规 | Result |
| A-5 | 命令面板零 axe 严重违规 | Command Palette |
| A-6 | 错题本零 axe 严重违规 | Review |
| A-7 | Progress 页零 axe 严重违规 | Progress |
| A-8 | 五页签全部零 axe 严重违规 | 全部（对应 `tests/e2e.mjs:1220` 的五页签 IA） |

**注意 A-4 与 A-5**：弹层类 UI 是 a11y 违规的重灾区（缺 role、缺 aria-modal、缺焦点困住）。

### 3.2 色彩对比度

| # | 断言 | 期望 |
|---|---|---|
| C-1 | 正文文字对比度 ≥ 4.5:1 | AA |
| C-2 | 大字（≥ 18.66px bold 或 ≥ 24px）≥ 3:1 | AA |
| C-3 | 打字"正确"状态提示**不是仅靠颜色**（有图标/下划线/形状差异） | **存在非颜色线索** |
| C-4 | 打字"错误"状态提示同上 | **存在非颜色线索** |
| C-5 | 焦点指示器对比度 ≥ 3:1 | AA |
| C-6 | 所有皮肤（主题）下均满足 | ⚠️ **有多个皮肤，需逐个测** |

**C-3 / C-4 是本产品的核心可用性指标**（见 §2）。
**C-6 特别重要**：`tests/e2e.mjs:173`【4】有皮肤切换。**每个皮肤都要过对比度**——深色皮肤下的红/绿对比度通常比浅色皮肤好，但浅色皮肤 + 浅绿可能不达标。

### 3.3 焦点管理

| # | 断言 | 期望 |
|---|---|---|
| F-1 | 命令面板打开后焦点落在面板内 | 在面板内 |
| F-2 | 命令面板内 Tab 循环不跑出面板（焦点 trap） | 困住 |
| F-3 | `Esc` 关闭面板后焦点**回归到打开它的元素** | 回归 |
| F-4 | 结算弹层打开后焦点落在弹层内 | 在弹层内 |
| F-5 | 结算弹层关闭后焦点回归 | 回归 |
| F-6 | 所有可交互元素 Tab 可达 | 全部可达 |
| F-7 | Tab 顺序符合视觉顺序 | 一致 |
| F-8 | 无"不可见但可聚焦"的元素（0×0 或 `display:none` 但 tabbable） | 无 |
| F-9 | 下拉菜单打开后方向键可导航 | 可 |
| F-10 | 下拉菜单 `Esc` 关闭且焦点回归触发按钮 | 回归 |

**F-3 / F-5 是最常被违反的两条**。`tests/e2e.mjs:370`【11.5】测了 `Esc` 能关面板，**但没测关闭后焦点去哪了**。

### 3.4 语义与屏幕阅读器

| # | 断言 |
|---|---|
| S-1 | 每个页面恰有一个 `<h1>` |
| S-2 | 标题层级不跳级（h1 → h2 → h3） |
| S-3 | 有 `main` landmark |
| S-4 | 有 `nav` landmark（页签） |
| S-5 | 所有 `<button>` 有可读文本或 `aria-label` |
| S-6 | 所有图标按钮（lucide-react 图标）有 `aria-label` |
| S-7 | 所有 `<img>` 有 `alt`（装饰性用 `alt=""`） |
| S-8 | 输入框有关联 `<label>` 或 `aria-label` |
| S-9 | 打字区有 `aria-live` 或等价机制播报当前进度 |
| S-10 | 结算结果有 `aria-live` 播报（分数/WPM） |
| S-11 | 虚拟键盘是装饰性的 ⇒ `aria-hidden="true"`（避免屏幕阅读器读 26 个字母按钮） |
| S-12 | 页签组用 `role="tablist"` / `role="tab"` / `aria-selected` |
| S-13 | 当前页签有 `aria-current` 或 `aria-selected` |

**S-11 特别值得注意**：虚拟键盘有 26+ 个按键，**如果没标 `aria-hidden`，屏幕阅读器用户会被 26 个按钮淹没**，完全无法使用。这是一个典型的"视觉上很有用、a11y 上反而有害"的组件。

**S-9 与 S-10 是本产品的关键**：打字练习的核心反馈（打对/打错/进度）如果只靠视觉，屏幕阅读器用户拿不到任何反馈。

### 3.5 响应式与缩放

| # | 断言 |
|---|---|
| R-1 | 200% 缩放（浏览器 zoom）下无横向滚动 |
| R-2 | 200% 缩放下所有功能可达（无被裁切） |
| R-3 | 320px 宽度（最小手机）下无横向溢出 |
| R-4 | 移动端横屏（667×375）下可用 |
| R-5 | 目标触控尺寸 ≥ 44×44 px（WCAG 2.5.5） |
| R-6 | 文本可重排（reflow）：320px 宽下不需双向滚动（WCAG 1.4.10） |

**已有基础**：`tests/e2e.mjs:361`【11】测了移动端视口 → **R-3 部分覆盖**（但未测横向溢出断言，只是渲染成功）。
**R-1 / R-2 完全无覆盖**——锚点缩放是 WCAG AA 的硬要求。

### 3.6 动效与动画

| # | 断言 |
|---|---|
| M-1 | 有 `prefers-reduced-motion` 媒体查询处理 | ⚠️ 当前无实现 |
| M-2 | 开启 reduced-motion 后：连击动画、confetti 关闭或简化 | |
| M-3 | 无闪烁内容（3 次/秒以上的闪烁）⇒ 癫痫风险（WCAG 2.3.1） | |
| M-4 | 打字时的光标闪烁频率在安全范围 | |

**M-2 有具体组件对应**：`canvas-confetti ^1.9.4` 是运行时依赖（`package.json`），连击/结算时会放彩带。**彩带是强烈动效，必须响应 `prefers-reduced-motion`。当前无实现、无断言。**

### 3.7 语言与本地化

| # | 断言 |
|---|---|
| L-1 | `index.html` 有 `lang` | ⚠️ 已有 `lang="zh-CN"`，但无断言 |
| L-2 | 切换到英文后 `<html lang>` 更新为 `en` | ❌ 无断言 |
| L-3 | 切换语言后所有 `aria-label` 同步更新 | ❌ 无断言 |
| L-4 | 无硬编码未翻译文案（视觉上残留中文/英文混合） | ❌ 无断言 |

**L-2 是一个具体且容易被忽略的 bug 面**：`tests/e2e.mjs:347`【10】测了 i18n 切换**能显示英文**，但 `<html lang>` 若没跟着改，屏幕阅读器会用中文语音引擎读英文（发音完全错乱）。**这是 i18n + a11y 的交叉缺陷，当前无任何覆盖。**

**L-4 与 `vite-spa-hardcoded-i18n-audit` 类问题相关**：双语站最容易出现"切换后还有一半是原语言"。

## 5. 优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| 🔴 P0 | **C-3 / C-4：正确/错误状态不只靠颜色** | 色觉障碍用户当前**完全无法使用**。这是功能可用性，不只是合规 |
| 🔴 P0 | **S-11：虚拟键盘 `aria-hidden`** | 否则屏幕阅读器用户被 26 个按钮淹没，完全不可用 |
| 🔴 P0 | **A-1~A-8：axe 全页面扫描** | 成本低、能一次发现大量问题 |
| 🟠 P1 | **S-9 / S-10：打字进度与结算的 `aria-live`** | 屏幕阅读器用户的唯一反馈通道 |
| 🟠 P1 | **F-3 / F-5：弹层关闭后焦点回归** | 最常见的键盘可用性缺陷 |
| 🟠 P1 | **L-2：切换语言后 `<html lang>` 更新** | 具体、易验证、影响发音正确性 |
| 🟠 P1 | **R-1 / R-2：200% 缩放** | WCAG AA 硬要求 |
| 🟡 P2 | M-1 / M-2：`prefers-reduced-motion` + confetti | confetti 是强动效 |
| 🟡 P2 | C-6：所有皮肤的对比度 | 有多皮肤，需逐个过 |
| ⚪ P3 | 高对比度模式（Windows HCM） | 覆盖人数少 |

## 7. 一句话总结给审计方

**键盘操作做得扎实（命令面板、背单词键盘流都有 E2E），但严格意义的无障碍是零覆盖：无 ARIA 断言、无对比度检查、无焦点管理、无屏幕阅读器验证、无缩放测试、无 reduced-motion。其中两条是功能可用性级别的问题——打字正确/错误的状态如果只靠颜色，色觉障碍用户无法使用；虚拟键盘若没标 `aria-hidden`，屏幕阅读器用户会被 26 个字母按钮淹没。**
