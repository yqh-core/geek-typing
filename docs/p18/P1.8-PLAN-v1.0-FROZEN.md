## §2 架构：统一 Content Type Contract

### 2.1 单一注册表（取代散落的 per-type 文件）

```ts
// src/core/content/types/registry.ts   （新增，唯一的类型事实源）
export interface ContentTypeDescriptor {
  type: ContentType
  status: 'active' | 'planned'          // 派生 SUPPORTED_TYPES：只有 active 才可查
  schemaVersion: number
  fields: FieldSpec[]                   // 字段定义（名/类型/必填/约束）
  validate(payload: unknown): ValidationResult
  query: {                              // → content-index 建索引维度
    index: IndexFieldSpec[]             //   倒排字段
    match: MatchFieldSpec[]             //   可检索字段（前缀/子串）
    sort: SortField[]                   //   白名单排序字段
  }
  learning?: {                          // → LearningService 消费适配
    contentIdOf(payload): string
    progressKind: 'word' | 'media' | 'unit'
  }
  i18n: { labelKey: string; unitKey: string }   // 类型维度文案（取代 bank.* 硬套）
}

export const CONTENT_TYPE_REGISTRY: Readonly<Record<ContentType, ContentTypeDescriptor>>
```

### 2.2 派生关系（消除"多处开关"）

| 现"散落开关" | 改为派生自 |
|---|---|
| `content-query.ts:133` `SUPPORTED_TYPES=['word']` | `activeTypes()` ← registry 中 `status==='active'` |
| `content-index.ts:12-13` 只索引 word | `indexPlan()` ← registry 的 `query.index` |
| 排序白名单 / `sort:'updated'` 退化 | registry 的 `query.sort`（无该字段则**明确不列为可排序**，不再静默退化） |
| 非词汇包无 UI 通路 | registry 的 `learning` 适配 + `i18n` |

### 2.3 全链一致性（评审 §② 的六段）

```
Content Type → Schema → Validator → Query Adapter → Learning Adapter → UI Consumer
     ↑            ↑          ↑             ↑                ↑                ↑
   registry    fields[]  validate()    query.*         learning.*       i18n.*
```

**新增类型（movie / podcast / news / grammar / course / lesson…）的完整动作 = 在 registry 里加一条**，
不需要改 Query、Index、UI 的骨架代码。这是 INV-6 的实质。

## §3 资产模型：AssetManifest ↔ ContentManifest

### 3.1 结构裁定

```
content/<type>/<id>/manifest.json
 ├── metadata        (id/title/type/version/…)
 ├── provenance      (包级：origin/provider/repository/importedAt/checksum/revision*)
 ├── license         (包级：spdx/name/url/attributionRequired/commercialUse)
 ├── relations[]     (contentId → contentId, RelationType)
 └── assets[] ─────► AssetManifest（**独立实体，随包生命周期**）
        ├── assetId     : string            // 全局唯一，形如 content:<type>:<ns>:<localId>#a:<aid>
        ├── kind        : AssetKind         // audio|video|image|subtitle|document|other
        ├── url         : string            // **必须远程**（/media/* 同源代理）
        ├── mime, bytes, checksum           // checksum 必填（sha256）
        ├── duration?   : number            // 媒体时长（秒）
        ├── lang?       : string            // 音轨/字幕语言
        ├── role?       : string            // subtitle: transcript|translation|karaoke
        ├── license     : ContentLicense    // ★ 显式；或 licenseRefPointing 到包内已声明许可
        └── provenance  : Provenance        // ★ 逐件来源（可能与包级不同）
```

### 3.2 三条所有权规则（冻结）

1. **Asset 不可跨包引用**——asset 生命周期严格随宿主包，禁止共享池。
2. **Asset 必须有许可**——允许两种写法：
   - 直接内联 `license {...}`；
   - 或 `licenseRef: "<包内许可标识>"`，**必须能解析到包内已声明的许可**。
   **禁止隐式继承**（不允许"没写就默认用包的"）——缺 = FAIL。
3. **包级与 Asset 级 provenance/license 并存不冲突**——包级描述"这批内容从哪来"，
   Asset 级描述"这个文件本身从哪来、能不能再分发"；两者都必填。

> 裁定理由：文本许可与媒体许可在现实中**经常不同**（如词表 MIT、音频 CC-BY-NC），
> 且"再分发权"是逐件的。隐式继承会在第一次遇到混合许可时静默产生合规错误——这类错误**事后无法补救**。

## §4 许可 / 来源硬门（入库前置）

### 4.1 门禁规则

| 规则 | 判定 |
|---|---|
| `license.spdx` 未知 / 缺失 | **拒绝**（复用 `license-policy.mjs decideLicense`） |
| `spdx` 非商用（如 CC-BY-NC） | **拒绝** |
| `commercialUse !== true`（面向公开分发的内容） | **拒绝** |
| `attributionRequired === true` 但无署名文本 | **拒绝** |
| `provenance.origin/provider` 缺失 | **拒绝** |
| `checksum` 缺失或与实体不符 | **拒绝** |
| Asset 缺 `license` 且无有效 `licenseRef` | **拒绝** |

### 4.2 门的性质变化（评审 §④）

v0.1 是"**validate 的必填校验**"；v1.0 升为"**入库前置硬门**"：

```
外部素材 → normalize → gate:license(硬门，不过则终止) → build → validate → ingest → 进内容仓
                              ↑
                    未过门的内容**不允许落盘到 content/**
```

并且该门进入 `release:gate` 与 P1.8 证据任务表 —— **任何 Wave 若引入新素材而未过门，证据矩阵判 FAIL**。
