### 4.1 e2e 预热探针的 CI flaky（本轮新定位，**根因未定死**，测试侧已去敏)

**现象**：`门禁③ 端到端` 偶发红，唯一失败项恒为
`❌ 预热探针：SW 缓存含 WARMUP_IDS 全部 chunk（[kaoyan, toefl]） — 轮询 120s 超时 — 0 个 words chunk`，
其余 169 项全过，探针把 120s 预算整跑满才退出。同一份 src 三笔 CI：**绿（515941c）/ 红（e4b6674）/ 绿（1f46ab9）**。

**一条被证伪的推断（先记这个，免得下个人重蹈）**：最初判「探针不等 SW 接管就 `reload` ⇒ 未接管页面的
动态 import 不经过 SW fetch handler ⇒ chunk 永不入缓存」。机制是真的（`src/main.tsx` 的 `warmBanks`
那段注释本就在防它：它 `await navigator.serviceWorker.ready` 后只等 `controller` 最多 5s），
但把探针改成「先按状态等接管（上限 30s）再 reload」之后，**独立证伪脚本仍然稳定复现 0 hits**，
诊断显示当时 `navigator.serviceWorker.controller` 恒为 false、`gt-shell-v3` 全程没建出来。
⇒「不等接管」不是充分条件，不能当根因写进结论。

**处置（不去追那个 reload 竞态，直接把出事的那一刀拔掉）**：
`tests/e2e.mjs` 的探针**删掉「清空 SW 缓存 + 重新加载」这一步**并**按状态等 SW 接管**（上限 30s）。
删 reload 的依据是它本就多余 —— 探针跑在 `mctx` 这个新开浏览器上下文（独立 profile ⇒ 独立 SW 缓存），
而该上下文只服务【14】的移动端手势用例、**从不切词库**，缓存里的 words chunk 只可能来自 idle 预热；
套件【15】用的是主上下文，两边共享不到（原先那条「防套件 15 污染」的前提不成立）。
**证伪性质不削弱**：把 `warmUpVocabulary` 整个删掉 ⇒ 该上下文再也不会拉 words chunk ⇒ 0 hits ⇒ 照样判红。
失败 Diagnosis 也拆开：现在会区分「SW 没接管 / 缓存没建出来」（**测不到**）和
「预热没把 chunk 写进缓存」（**测到没通过**），不再混成一句「超时」。

**⚠️ 同时暴露的生产侧缺口（只登记、本轮不改）**：慢设备上 SW 激活超过 5s 时，
`warmBanks` 会在未接管状态下 import ⇒ 预热静默失效（首次离线仍切不了大词库），
而 `Promise.allSettled` 把失败吞了、无任何日志。这条**不是 P18 引入**，也不在本轮改动范围内 ——
`warmBanks` 的 controller 等待上限（5s）与吞错行为（无日志）应单独立项。
