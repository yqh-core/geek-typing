## 2. 候选判定：为什么只动这两刀

| 候选 | rendered | 判定 |

| **`canvas-confetti`** | 19.76 KiB | ✅ **做**。只用在一个文件 `src/lib/confetti.ts`，调用点核查过都在「用户完成操作后的装饰性触发」（Memorize 只在 `tab==='memorize'` 且 deck 已空时触发；ResultOverlay 只在 `typing && finished` 渲染），**不在首屏** |

| `content/query/content-query.ts` | 0.89 KiB | ⏸ **不做**（下面 §3 说清这条为什么看着像坑、其实不是） |

## 5. 顺带发现的真缺陷：bench 会把 INV-1 冻结区改脏

**发现过程**：`scripts/bench-boot.mjs:43` 把可变基线写进 `docs/audit-package/_generated/perf-baseline.json`
—— 那是 **INV-1 冻结区**。我做了证伪：往这个文件追加**一个空格**，再跑 `verify-p17-frozen.mjs` ⇒
`P1.7 冻结基线保护：❌ FAIL`，**EXIT=1**。随后 `git checkout` 还原。

⇒ 也就是说：**任何跑过一次 `npm run bench:boot` / `bench:content` 的人，INV-1 门都会红**，只是 STATUS 里没人去跑 `verify:p17-frozen` 才一直没爆。
根因是设计问题：可变基线不该待在冻结 manifest 的覆盖范围内。

**处置（最小刀，不搬文件、不重写历史）**：`bench-boot.mjs` / `bench-content.mjs` / `gate-perf.mjs` 三处写入路径改到
`docs/_generated/perf-baseline.json`；冻结区里那份**原样保留、只读不写**，它仍是已提交的种子文件。
复核（重定向取真实退出码，不用管道）：`verify-p17-frozen` **EXIT=0 / ✅ PASS**；`grep` 全 `scripts/` 已无写入 `docs/audit-package` 的 `writeFileSync`。
