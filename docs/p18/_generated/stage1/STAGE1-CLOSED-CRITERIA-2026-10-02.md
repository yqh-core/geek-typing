## §4 本轮换来的两条工程经验（写下来，别让下一任重踩）

**① 判据要锁「调用点的接线」，不能只锁函数内部。**
`L5d` 第一版的自检是 `asciiPhraseProbes(json, [], decoy)` —— 自己重算一遍、把 decoy 当 excludeText 喂回去，
于是只要函数内部那句 filter 还在就恒绿。我复核时把 `:432` 的 `scanSrcText()` 换成 `''`（接线拆掉），
**L5d 依然 `✓`** —— 假绿。最终改成让函数通过 `dropStats` 出参上报「本次实际踢掉几条」，
`:432` 拆掉 ⇒ `srcDropped = 0` ⇒ L5d 判红（实测：`✗ L5d ... 踢掉了 0 条候选（应 > 0）`）。
**复验记录（本轮独立跑的，不是引自实现者的报告）**：
- MUT-1 `:432` → `''` ⇒ L5d 判红 ✅
- MUT-3 撤销 `hitQuote`（`:354`）⇒ L5c 判红：`✗ L5c ... 探测集混进了含 `"` 的候选` ✅
- 两条都还原 ⇒ `11/11 恰好判红`、check-bundle exit 0、工作树空 ✅

**② 按行号注入 mutation 会在二次提交后打空。** 我第一次复核按旧行号 sed，打到注释行上，
文件压根没变却显示「L5d 还是绿」—— 差点误判成假绿，实际是**注入没生效**。
**教训：mutation 注入必须带 `assert t != s`（注入前断言字符串确实命中），否则「没红」和「没注入」分不清。**
