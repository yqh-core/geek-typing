## ① P1.8 证据树 → 按波次独立根（已实施）

**裁定：恢复 P1.7 的「按波次独立证据根」原则。证据根 = `docs/p18/_generated/evidence/<波次名>/`。**

### 问题（评审原话要点）

整个 P1.8 系列共用同一个证据根 `docs/p18/_generated/evidence/P18/`、matrix 每次重生成
→ **每跑一轮，上一轮全部产物变 orphan**（截图时已累积 27 个）；
而 `evidence-verify.mjs` 把 orphan 写成恒真判据（`check(..., true, ...)`）且措辞为
"历史失败轮留档"。**这不是文档美观问题，是证据语义被污染**：orphan ≠ historical failure，
它可能只是"上一轮被新 run 取代 / 证据根重建 / 路径变化 / matrix 重建"。
把 orphan 一律判通过，会让**当前有效证据**与**历史遗留证据**混进同一个验证语义。

### 实施（commit `4c25317`）

| 项 | 内容 |
|---|---|
| 任务表查找 | 改为**族键**：`TASKS[WAVE] ?? TASKS[FAMILY]`，`FAMILY = WAVE.split('-')[0]`。`P18-A`/`P18-B`/… 各用自己的证据根，**共用 `P18` 那份任务表**（Plan §6 要求共用，不破） |
| 产物退役 | 每个 task 生成前，把该波次顶层里同任务的上一代产物 `renameSync` 到 `<波次>/_superseded/`（**用 rename 不用 unlink** —— 本机 safe-delete shim 会拦删除）。于是**波次顶层 == 恰好 matrix 引用的那批文件**，orphan 才有资格当严格判据 |
| attempt 递增 | `attempt = (顶层 + _superseded 里同波次同任务计数) + 1` → `R01`/`R02`/…（评审要求"retry 要有 run/version 概念"）。全新波次仍从 `R01` 起，与 P1.7 既有产物零回归 |
| orphan 语义 | `P18*` → **严格判据**（命中即 `BROKEN` / exit 1）；`W*` → 保持通过语义但**措辞改准**（"历史轮留档、不计入判定"） |
| `_superseded/` | 子目录，非递归扫描天然不参与 orphan 判定；verify 增加**信息性**输出（数量 + 最近 3 名） |

### 为什么 `W*` 不追溯改判（有实测依据，不是姑息）

只读统计各 `W*` 目录的顶层 orphan：

| 目录 | 顶层 .txt | 被引用 | orphan |
|---|---|---|---|
| **W0** | 28 | 14 | **14** |
| **W3** | 46 | 23 | **23** |
| `verify/`（游离目录，无 matrix） | 5 | 0 | **5** |
| W1A/W1B/W1C/W1D/W2A/W2B/W2C/W4/W5C/W5D | — | — | 0 |

即：**若当年就上严格 orphan，W0 与 W3 会判红。** P1.7 证据链已封版且位于 INV-1 冻结区
（`docs/audit-package/**`，禁止写入 → 连"重跑修好"都不允许）。追溯改判等于用今天的标准
去推翻一份已经冻结、且**按设计不可重跑**的历史证据 —— 那不是提高标准，是制造不可修复的破窗。
所以：**标准向前生效，不向后追溯。**

### 迁移映射

- `P18-0/` ← P18-0 的 12 个产物 + 复活并**重基**的 `bb17148` matrix（`wave` → `P18-0`，
  `evidence` 路径 `P18/` → `P18-0/`）。**产物文件与 runId 零字节改动**（`artifactSha256` 仍匹配）。
- `P18-A/_superseded/` ← 前两代（gen2 = `ee1fe29`、gen3 = `99764f6`）共 30 个产物
  + 4 份 matrix 快照 + `README.md`（说明每一代对应哪个 commit、以及**gen2 是在带着
  "Node 侧类型白名单漂移"缺陷的 `ee1fe29` 上全绿的** —— 它是真实结果，但会误导，
  所以不能当有效证据）。
- 旧单根 `docs/p18/_generated/evidence/P18/` 已删除；新增系列级 `README.md`。

### 证伪证据（不会失败的门等于没有门）


### 校验器的负路径自证（在仓库外临时树做，未触碰仓库）

| 构造的坏输入 | 期望 | 实测 |

## ③ AssetId 规范（RULED —— 定死一种）

**裁定：采用 Plan §3.1 的形态，废止 `asset.ts` 现存的形态。**

```
assetId = <宿主包 ContentId>#a:<assetLocalId>
示例   = content:vocabulary:ecdict-ietf:ielts#a:a-0007
```

### 为什么（这决定了 `asset.ts` 必须改，不是二选一都好）

1. **所有权必须写进标识**。三条所有权规则第 1 条是"**Asset 不可跨包引用，生命周期严格随宿主包**"。
   用 `<宿主 ContentId>#a:<localId>` 时，"这个 asset 属于哪个包"是**语法可见**的，
   `assertAssetOwnedBy(assetId, hostContentId)` 可以退化成纯字符串前缀判定。
   而 `asset:<kind>:<namespace>:<localId>` 里 `namespace` 只到**来源族**粒度
   （如 `ecdict-ielts`），**表达不了"属于哪个包"** → 规则 1 只能靠运行时遍历校验，弱一层。
2. **`kind` 放 ID 里是重复且会漂**。asset 的 kind 已经写在 asset 记录里；同一份文件从
   `audio` 改判为 `subtitle` 不该导致 ID 变化 —— ID 必须只由**所有权 + 本地键**决定。
3. **不引入第二套 ID 文法**。仓库已有 ContentId 的 4 段式规范与
   `normalizeLocalId` / `isStableLocalId` / `parseContentId` 一整套，且已被
   `content:validate` 判据 3 约束。复用比新造一套可控。

### 落点（P18-B 实施）

- `src/core/content/model/asset.ts`：
  - **删除** `makeAssetId(kind, namespace, localId)`；
  - **新增** `makeAssetId(hostContentId: string, assetLocalId: string): string`
    与 `parseAssetId(id): { hostContentId, assetLocalId } | null`（正则 `<ContentId>#a:<localId>`，
    localId 复用 `normalizeLocalId`/`isStableLocalId` 的口径）；
  - **新增** `isAssetOwnedBy(assetId, hostContentId): boolean`（纯前缀判定，供校验器与门调用）。
- `AssetRef.assetId` 的注释同步改成新形态；顶部注释里那句 `asset:<kind>:<namespace>:<localId>`
  必须一并改掉，**不许两种形态同时在代码里出现**（评审原话：不要让两种格式同时进入代码）。
- `content:validate` 的"broken asset"判据（现 `validate.mjs:407-416`，只在 `manifest.assets`
  存在时校验 URL）扩为：assetId 语法 + **归属断言**（asset 必须属于本包）。
- **单一实现**（防止 P18-A「12→14 白名单漂移」同型事故重演）：assetId 语法/归属/解析规则
  只允许有**一份**实现 —— 放在 `scripts/content/asset-rules.mjs`（新），由 `validate.mjs`
  与 `scripts/gate-license.mjs` **共同 import**（详见 ④-7）。

## ④ 包级许可语义 + licenseRef（RULED）

**裁定：引入「包级具名许可表」，asset 许可二选一，禁止隐式继承。**

### 现状（这是必须先解决的原因）

许可**只**存在于 `sources[].license`（18 个包各 1 条 source）。`PackageManifest`（`schema.ts:24-79`）
**没有**包级 `license`，也**没有** `provenance`。
→ 计划要求 `licenseRef` 指向"包内已声明的许可"，可是**当前没有可指向的目标**。
所以"先补齐包级许可语义，再定义 licenseRef" —— 顺序不能反。

### 裁定内容

**④-1 新增包级具名许可表**（`PackageManifest`）：

```ts
/** 包级许可表：id → 许可。资产用 licenseRef 指向这里的 id，即「声明式继承」 */
licenses?: Record<string, ContentLicense>
```

- 是**具名表**（`Record<string, …>`）而不是单个 `license` 对象：因为一个包里
  "词表 MIT / 音频 CC-BY-NC"完全可能并存，单个对象表达不了。
  评审的原话是"文本许可与媒体许可在现实中**经常不同**（如词表 MIT、音频 CC-BY-NC）"。
- **向后兼容**：现有 18 个包都不带 `licenses`，不构成破坏。

**④-2 Asset 许可二选一，缺失即 FAIL（禁止隐式继承）**
每个 asset 必须**显式**满足其一：
- 内联 `license: ContentLicense`，或
- `licenseRef: string`，且**必须能解析到 `manifest.licenses[ref]`**。

不许"没写就默认用包的"。"缺 = FAIL"（Plan §3.2 规则 2 原话）。
`licenseRef` 解析不到 → FAIL（不是 warning）。

**④-2b 二选一必须是编译期互斥的，不能只靠运行时校验。**
用「互斥字段」表达，让"两个都写"与"两个都不写"在 `tsc` 阶段就报错：

```ts
type AssetLicense =
  | { license: ContentLicense; licenseRef?: never }
  | { licenseRef: string; license?: never }
export type AssetManifest = AssetBase & AssetLicense
```

类型锁"**写法互斥**"，运行时锁"**引用有效**"（`licenseRef` 必须命中 `manifest.licenses`）——
两者缺一不可，不能只有运行时那一半。

**④-3 包级与 Asset 级并存，互不替代**
`licenses`（包级表）与 asset 的 `license`/`licenseRef` **都必填**，
但只要包内**没有**资产，就不要求 `licenses`（否则现有 18 个无资产包会集体破坏）。
精确口径：

> **包级 `licenses` 与包级 `provenance` 必填 ⇔ 该包声明了非空 `assets[]`。**

这是对 Plan §3.2 规则 3 的**实施口径细化**，不是放松：一旦加了第一个资产，
包级两件套就变成强制，且"包级 ≠ 资产级"——两者必须各自为真。

**④-4 包级 `provenance`**
新增 `PackageManifest.provenance?: Provenance`（复用 `src/core/content/provenance.ts:24-35`
的 `Provenance` 类型）。同 ④-3 的条件必填。

**④-5 `sources[].license` 语义不变，且不得互相 fallback**
`sources[].license` = **载荷来源许可**（"这份词表从哪来、什么许可"），
`licenses` = **可被资产引用的许可表**。
两者**职责分离**：`licenseRef` **只能**解析到 `licenses`，**绝不能**回退到
`sources[].license` —— 否则就变成隐式继承，正是要禁的。

**④-6 asset 级 `provenance` 必填（复用 `Provenance`，字段名以既有类型为准）**

每个 asset 必须带 `provenance`，类型 = `src/core/content/provenance.ts:24-35` 的既有
`Provenance`（**不新建类型**）。其必填字段是 **`provider`**（`Provenance.provider: string`），
`repository?` / `path?` / `revision?` / `retrievedAt?` 均选填。

> ⚠️ **口径纠正（本文 v1.0 初稿此处写错，以下为准）**：初稿写成"`origin` 必填"是错的 ——
> `Provenance` **没有** `origin` 字段。带 `origin` 的是 `ContentSource`（即 `manifest.sources[]`，
> 字段为 `origin` / `provider` / `repository` / `importedAt` / `checksum` / `license`）。
> 这是两个不同概念，**字段名不许混用**：
> - `Provenance`（**包级 + asset 级**）= 溯源，必填 `provider`；
> - `ContentSource`（`sources[]`）= 载荷来源，必填 `origin`，并**独占**
>   `importedAt` / `checksum` / `license`。
>
> 不许把 `importedAt` / `checksum` 塞进 `Provenance`；也不许为 asset 另造一个带 `origin`
> 的"迷你 provenance"。**一个概念一个类型**——否则 P18-B 一落地就会同时存在两种溯源口径。

**④-7 资产/许可校验同样只允许一份实现**

`gate-license.mjs`（新，入库前置硬门）与 `content:validate`（入库后校验）要检查**同一批规则**
（assetId 语法 / 归属 / 许可二选一 / `licenseRef` 解析 / 包级两件套条件必填）。
两份手写实现 = 下一场「12→14 白名单漂移」，只是这次漂的是资产规则。

- 规则集中在 **`scripts/content/asset-rules.mjs`（新）**，导出纯函数
  （`checkAssetIdShape` / `checkOwnership` / `checkLicensePresence` / `resolveLicenseRef`）。
- `validate.mjs` 与 `gate-license.mjs` **只 import**，自身不含规则逻辑。
- 由 `gate-content-type-contract.mjs` 新增判据 **H3**（禁止 `asset-rules` 规则的第二份副本）
  上锁 —— 与 H1/H2 同一手法：**权威只有一处，一致性由机器证明，不靠注释**。
- `license-policy.mjs` 仍是许可判定矩阵（`decideLicense`）的唯一来源；
  `asset-rules.mjs` **不得**复制该矩阵，只调用它。

**④-8 §4.1 门禁规则必须**全表机器化**，并由覆盖矩阵与 Plan 逐行对账**

冻结 Plan §4.1（`docs/p18/P1.8-PLAN-v1.0-FROZEN.md:151-161`）列了 **7 条**规则，§5 门禁总表
（`:183`）声明 `gate:license` 覆盖「**§4.1 全表**」。但初版实现只机器化了 5 条，另 2 条
—— `commercialUse !== true`、`attributionRequired === true` 但无署名文本 ——
**没有任何判据覆盖**，只在 `P1.8-RELEASE-GATE-CONTRACT.md` 里留了一句"口径说明：本波未机器化"。

**这就是"靠注释"** —— 与「体积门假绿」「12→14 白名单漂移」同一类失败：门看起来绿，
但它宣称覆盖的东西并没有被检查。裁定：

1. **7 条全部机器化**。`decideLicense` 增两条（`commercialUse !== true` → 拒绝；缺失也算不 true。
   `attributionRequired === true` 且 `attribution` 为空 → 拒绝）；`gate-license.mjs` 增两条
   （source 的 `origin`/`provider` 必须非空；`sources[].checksum` 必须等于载荷实体完整 SHA-256）。
2. `ContentLicense` 新增 **`attribution?: string`（署名文本）** —— 让"无署名文本"这条**可判定**，
   而不是留在说明文字里。
