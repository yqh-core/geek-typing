### 3.1 允许重开的例外（防止本规则变成"永远不许修 bug"）

以下情形**允许**触碰已闭合对象，但必须留下同等级别的机器证据与书面记录：

- **E1 判据本身存在假通过漏洞**：发现某条判据在应当判红的输入下仍判绿（假通过），可修复该判据，并必须补一条证伪自检证明"修之前能绿、修之后能红"。
- **E2 线上出现真实故障**：生产环境出现可复现的真实缺陷，且定位到已闭合范围内的代码/判据，可修复并新开证据波次记录。
- **E3 安全/合规问题**：出现安全漏洞、凭据泄露或合规风险，按最高优先级立即处理，事后补齐证据与说明。
- **E4 外部平台强制变更**：如 CI runner / action 版本到期弃用、依赖平台下线等被动变更，允许适配，并登记影响范围。

非上述情形的一切改动（尤其是"看着可以更整齐"的重构、重命名、格式清理、判据措辞优化），
一律**不在 P18 已闭合范围内进行**，转入 §5 的后续阶段。
